# PRISON 产品系统

[English](product-system.en.md) · **简体中文** · [Türkçe](product-system.md)

PRISON 把一个人的需求变成清晰的任务提示词，让他可以在自己选择的 AI 中使用。议会桌和竞技场把这项工作讲述成一个易于理解的场景。
用户的价值来自：目标和限制得到保护、能够检查各个提案，以及能够改进结果。

## 用户能掌控什么？

| 介入方式 | 实际效果 |
| --- | --- |
| 目标、不能改变的限制、输出格式 | 进入分析和提示词契约。 |
| 回答缺失信息的问题 | 更新任务计划和下一个提示词。 |
| API 连接、模型、专长和深度 | 决定新一次生成的分析/审核团队。 |
| 角色与动作指令 | 播放所选角色的关节动作；观看会暂停。 |
| 在其他 AI 中试用提示词 | 检验提示词对用户目标是否有用。 |
| 对所得结果的反馈 | 通过真实的修订生成下一个版本。 |

动作从不产生投票、分数或获胜者。评审团的状态只依据记录下来的模型评估。用户指令与表演之间的区别会在界面中用一句简短的话说明。

## 学习与参与感

需求界面提供目标/限制/输出提示；由于按钮会改变可见的文本，用户能看到自己是如何塑造提示词的。规划阶段提供补全缺失上下文的机会。
保存下来的候选和评审展示了哪个提案改变了、为什么改变。结果界面让复制完整文本、在目标 AI 中试用和提供反馈成为清晰可见的步骤。

指南可以关闭，并在相关阶段显示。失败的记录绝不会被当作完成的提示词展示；只提供查看和重试的途径。本地引擎、单个模型和真实的多模型工作
都按各自的证据来描述。不会编造 AI 的情感、推理过程或成功保证。用户的掌控和进展是可见的；不使用隐藏的压力、虚假的成功，
或让人因为没有继续而感到失去什么的奖励机制。

## 个人 AI 团队

一个连接由服务商类型、HTTPS 地址和保存在服务器上的密钥组成。模型选择与连接 ID 一起保存。分析模型和将要使用提示词的目标 AI
是不同的概念。议会桌由 3–6 个不同的模型组成；同一模型的副本不算独立的意见。专长决定了该模型的审视角度。

支持：NVIDIA、DeepSeek、OpenAI Responses、Anthropic 结构化输出以及 OpenAI 兼容的 Chat Completions JSON。模型访问在预检中测试；
参与不足时，工作会给出清晰的错误。不会向已保存的团队添加用户未选择的替补模型。保存设置不会改变正在进行的操作。
修订冲突时会保留表单，并提供加载最新记录的选项。

密钥位于服务器文件中；该文件没有加密。密钥从不出现在 DTO、浏览器草稿或错误消息中。API 地址改变时，之前的密钥不会被自动沿用。
保存不会进行远程生成；它只改变下一次操作的设置。

## 动作与装备

`gesture-library.ts` 包含五组共 50 个不同的多关键帧动作片段：问候、思考手势、讲解、反应和休息。片段对身体、头部、翅膀、腿和尾巴关节
施加有限的角度/动作。每个片段都以中立姿势开始和结束。坐姿、携带物品和减少动态效果的偏好都会被考虑。

`scene.ts` 在真实事件之后为角色挑选片段。这一选择在回放中可以重现，并且不会立刻重复同一角色的上一个片段。用户指令通过场景中的
`playGesture` 运行；界面会先清除视觉动作、暂停观看并显示舞台。在片段播放前，镜头会把所选角色纳入画面；字幕把这个动作称为用户的动作请求。
在减少动态效果模式下，镜头不会移动。与此同时，服务器上的操作继续进行。`gesture-director.ts` 是一个经过测试的辅助模块，
将来可用于队列/优先级管理；目前没有接入场景。

装备拿在翅膀/手上或背在背上；它跟随骨骼连接。武器代表的是评审标准：目标契合、上下文完整、限制清晰、执行清晰、输出清晰和目标 AI 适配。
舞台徽章中没有表情符号装备列表。不会把奖励或购买展示得好像已经发生。

新的片段以唯一 ID、类别、时长和关键帧加入同一个目录；动作选择列表会自动扩充。新片段必须通过中立端点、有限/有界的关节数值、
坐姿以及被占用翅膀的规则。
